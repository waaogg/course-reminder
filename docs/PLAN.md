## 用户已确认的边界

本机开机时自动采集即可；通知渠道不限定，由助手选取有效方式；接受必要时重新登录，但应尽量减少频次。第4项回答“AB”暂按正文与附件/图片均需覆盖理解。老师要求日期与系统截止时间必须分开保存和呈现，各自调度提醒，不能合并成一个截止时间。以下内容按此更新；需求确认不等于已经开始开发。

## 为什么做

把中国大学 MOOC（含 SPOC）和思源学堂中参加课程的作业、测验、考试、互评及通知要求统一呈现，及时发现新任务、截止变动和未完成事项，减少漏交。

本轮已有具体证据：思源作业系统时间和老师文字日期不一致；普通 MOOC、SPOC 的页面结构不同；已经提交的测验仍显示未来截止时间。仅汇总日期不足以解决问题。

## 全自动的范围

配置完成后，程序自行发现课程、遍历任务和公告、读取截止时间及提交状态、持久化并比对变更、调度提醒。不要求用户逐门打开网页、不要求每次点击同步、不要求复制 Cookie。

必须区分：
- 自动采集：正常登录有效期间，后台自主运行。
- 认证介入：首次登录，以及平台要求重新登录/验证码/二次验证时，由用户完成；过期立即提示，不得伪装成功。尚不能承诺永不过期。
- 运行条件：本机运行依赖电脑开机、网络可用、程序常驻；关机或休眠时不能继续采集。日常 Chrome 和应用主界面可以关闭，采集程序必须仍在后台运行。
- 提醒条件：已知任务离线仍可由运行中的本机程序提醒，但离线时无法获知老师的新任务或改期；电脑关机要靠常开设备或外部日历/推送承担已同步提醒。

## 选项比较

| 路线 | 自动化能力 | 代价与边界 | 判断 |
|---|---|---|---|
| 本机常驻应用＋专用浏览器采集 | 自动定时发现所有已选课程并采集；不依赖日常浏览器标签页 | 电脑需开机；认证失效需重新登录；需验证后台兼容 | **第一阶段推荐**，登录与数据留本机，便于验证 |
| 常开设备/服务器运行同一采集器＋手机推送 | 主电脑关机仍可采集和提醒 | 需真实验证学校网络、异地登录、认证续期和通知通道；凭据保护与运维成本更高 | 若“关机也要持续采集”为硬要求，完成验证后采用 |
| 纯浏览器扩展 | 可以定时采集，且易复用浏览器登录 | 浏览器/设备生命周期影响运行；只采已打开页不能算全自动 | 不作为当前全自动需求的首选 |

用户已选择本机开机期间运行，采用第一条路线。服务器路线仅保留为未来扩展，不进入当前交付范围。本轮不部署也不创建定时任务。

## 推荐架构

```text
定时调度器（启动补采、计划同步、失败退避）
    ↓
独立持久浏览器配置（用户完成初次登录）
    ↓
思源适配器 │ MOOC 新界面适配器 │ SPOC 旧界面适配器
    ↓
课程发现 → 列表与详情 → 公告正文 → 提交/互评状态
    ↓
规范化、变更检测、日期冲突识别
    ↓
SQLite 本地持久库 → 统一任务界面 → 通知队列
```

建议 Node.js/TypeScript 作为采集与调度核心，Playwright 驱动专用浏览器，SQLite 存储，桌面托盘与任务界面在采集闭环验证后选定包装方式；这些是设计建议，不是已安装或已验证的项目依赖。

专用配置由用户手动登录；常规采集后台运行，遇认证交互再显示登录窗口。无头模式如不兼容，验证有界面但后台运行的专用进程；不能承诺站点接受无头访问。无需接管用户日常 Chrome 配置或开放远程调试端口。

尽量减少登录：跨重启复用专用登录状态，不在每轮同步创建全新空配置，不主动登出；按平台正常会话流程更新状态。确认证书、网络或页面加载失败与认证失效的区别，仅在确实需要交互时通知登录。登录频率需实测，不能用高频访问承诺延长会话，也不默认保存密码。

数据获取顺序：先以真实可读页面打通闭环；开发时观察页面实际发出的读取请求，若证明结构化接口覆盖完整且可正常授权访问，则用于加速；保留页面适配作为回退。**没有已确认的官方或内部 API，不预写猜测的接口。**

## 同步设计

初始建议：启动、网络恢复和系统唤醒后补采；默认每 30 分钟增量同步，每日一次完整课程与任务校验。该频率是待调优配置，不是已验证的平台限额。

自动遍历当前学期和仍有活动的已选课程，发现新选课与新任务；支持排除已结束课程，但不得因任务暂时不见就删除。课程发现应有分页/懒加载终止条件。长周期任务可降频，临近任务的状态同步可适度加频，按平台错误率退避。

任务详情和公告缓存内容指纹，正文不变时复用解析结果。记录每个平台、课程、入口的最近成功时间、最后尝试时间和错误。单门课失败时其余照常，但整轮结果标注部分成功；不能让首页成功掩盖课程采集失败。

串行或低并发执行同平台访问，避免同一配置被多个进程同时占用。界面显示计划下次同步时间和数据新鲜度。后台崩溃重启后从数据库恢复计划，错过的提醒补发并去重。

## 统一数据模型

课程主键包含平台、账号本地隔离标识、课程 ID 与学期/期次；任务主键再包含任务 ID 和阶段。名称相同不自动跨平台合并，允许用户建立关联但保留各自任务。

任务至少保存：标题、课程、平台、类型、原任务链接、系统开始/截止/补交时间、独立的老师要求日期列表、原文证据、时间精度、时区、提交状态、互评状态、首次发现和最后成功校验时间、内容版本、人工覆盖及提醒记录。老师日期可能来自正文、公告、图片、附件，需记录来源和识别/确认状态。提醒身份须包含日期来源及该要求的独立标识，避免两类提醒相互覆盖或误去重。

时间按 Asia/Shanghai 显示，内部保存明确时间戳和来源时区。只给日期的要求保持日期精度；“下周二”等相对日期须依赖公告发布时间及上下文，否则进入待确认。不得默认所有任务都是 23:59，实际已看到 MOOC 23:30。

状态至少区分未提交、已提交待评、已完成、互评未完成、需重交、已逾期、未开放、未知。分数不可见、成绩为零、未评分均不得单独推导为未提交。用户本地勾选完成不能伪装成平台已提交。

## 日期冲突与正文理解

根据用户第5项回答，列表与系统字段确定“系统截止时间”，教师说明等内容确定独立的“老师要求日期”；两栏分开展示。两者不同可以显示冲突提示，但不能取最小值合并成一个实际截止时间，也不能用一方覆盖另一方。分别生成有来源标签的提醒。

把“老师要求：10 月 27 日交（未给具体时刻） / 系统截止：10 月 30 日 23:59”作为首要真实验收样本。两项分别保留并提醒。日期无具体时刻时可按可配置的当天晨间提醒政策预警，但提醒文案必须说明老师未给时刻；提醒策略时间不是从老师原文提取的截止时刻。

最终覆盖目标按用户“AB”暂定为结构化字段、可见正文及附件/图片/教学进度表。先实现正文，再接入附件文本提取及本地OCR；它们属于计划范围，不能无限期忽略。每项标记已解析、待确认、格式暂不支持或采集失败，任何未处理附件不得当作“没有老师要求日期”。可选 AI/OCR 用来提出候选，不自动决定模糊时间；向外部模型发送正文或附件需另外确定服务及数据范围。

## 提醒和界面

默认建议对有明确时刻的每类期限分别提前 3 天、1 天、3 小时提醒，可配置；老师仅给日期时使用日期精度提醒策略。新任务和提前截止单独提醒。日期冲突、登录失效、持续同步失败有独立故障提醒。有效提交后停止平台已完成阶段催交，仍有互评则保留互评提醒；老师可能要求线下提交，不能因平台已提交就自动认定老师要求也已完成。两类期限分别更新和取消提醒，各自完成状态要有证据或由用户确认。

按“今天 / 未来 7 天 / 逾期 / 待确认”展示，可按平台和课程筛选；每条分别显示“老师要求日期”“系统截止时间”，缺失项明确显示未发现/尚未检查，不把一项推算为另一项；同时显示状态、最后同步时间、来源原文及一键跳回。逾期标记须指出是哪一种要求逾期。通知的生成、交给操作系统、用户确认分别记录，不能把通知 API 成功等同于用户已经看到。

用户不限定通知渠道，首版设计为桌面通知＋应用内通知中心，并在用户电脑上实际测试。重要提醒未确认时可按配置再次提示并提供稍后提醒，避免无上限重复弹窗；如果实际通知不可达，再确定可行的备用渠道。手机端、邮箱及外部通知服务尚无具体接收地址或通道，不擅自填写或发送。静态 ICS 导出可作为辅助，但无法自行反映未来改期，不能冒充自动日历订阅。现阶段没有发送任何外部通知。

## 开发顺序与验收

1. **自动采集可行性样机**：独立登录、自动发现课程、思源任务/MOOC/SPOC 各取真实样本，连续两次计划同步无需点击网站。登录持久性、后台运行与读取范围不过关时先解决，不先美化界面。
2. **采集与状态完整性**：覆盖全部可访问已选课、分页与未开放项，持久化去重，保留证据；一项失败不清库。
3. **老师要求覆盖与提醒闭环**：附件文本及本地OCR、统一任务页、两类日期分栏及分别提醒、文字冲突、完成过滤、重启补发、通知去重。
4. **打包与持续运行**：实现用户已选本机路线的托盘、自启/进程恢复；在用户电脑验证通知可达及登录复用，不部署服务器。

可核对的硬指标：
- 本次快照仅作首轮对照：思源 12 门课 / 首页 7 条待办，MOOC 3 门 / SPOC 5 门；开发当天人工复核真实平台后更新基线。
- 连续两次自动同步不新增重复任务，关闭主界面后仍能运行下一轮；关闭日常 Chrome 不影响专用采集器。
- 日期冲突样本须分别显示老师要求10月27日、系统截止10月30日23:59，两项提醒互不覆盖；MOOC 23:30 不被改为 23:59；已有效提交记录不被标为未交；平台提交不能自动消除尚未确认的线下要求。
- 代表性附件及图片中的日期能提取并保存来源，低置信度项待确认，无法处理的项目有可见状态，不伪报完整覆盖。
- 模拟截止提前、延后、登录过期、断网、部分页面失败、瞬态空列表、重启：不丢旧数据、不伪报全量成功、不重复催交，故障状态可见。
- 所有真实平台验证保持读取范围，不通过真实提交作业来测试状态变化。
- 具体执行命令等实现存在后再写，不能在空项目里声称测试已通过。
