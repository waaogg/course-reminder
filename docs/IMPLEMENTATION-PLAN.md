## 1. 目标与已确认边界

为单个用户制作 Windows 本地桌面应用，在电脑开机、用户已登录 Windows 且程序运行时，全自动采集中国大学 MOOC（普通课程＋SPOC）与西安交大思源学堂中的已选课程、学业任务及时间要求，提供提醒。

用户已确认：
- 电脑关机不需要继续采集，不部署服务器。
- 通知方式可由开发者选定；首版桌面通知＋应用内通知中心，须在用户机器实际验证。
- 首次或过期时可以手动登录，应尽量减少次数。
- 第4项“AB”暂按正文、附件、图片、教学进度表均需覆盖理解，可分阶段实现。
- **老师要求日期与系统截止时间分别保存、展示、提醒，互不覆盖。**
- 新发现、方案、开发进度与失败经验必须持久归档。记忆不包含密码、Cookie、Token。

范围不包括自动答题、提交作业、代做互评、修改平台内容、公开发布、云同步。用户后续批准可配置AI服务接入，Key自行配置，发送课文需明确设置同意，服务费用由提供商计费。只读采集允许平台产生正常页面访问记录，不将其宣传为绝对无副作用。

“全自动”指正常认证有效期内无需逐门打开课程、点同步或复制Cookie。验证码、二次验证仍由用户完成。自动采集不是承诺无遗漏；覆盖情况和失败必须可见。

## 2. 已有证据、环境与技术选择

已有事实详见 `RESEARCH-2026-10-27.md`：思源快照12门课、首页7条待办；MOOC有3门普通课、5门SPOC。已见两类MOOC界面、23:30截止、有效提交记录、学生互评要求，以及老师要求10月27日交而系统10月30日23:59截止的冲突。

本轮环境探查：Windows x64，Node v24.19.0、npm 11.17.0、Git 2.52.0；当前目录没有Git仓库，只有规划与记忆文档。未安装应用依赖，不把主机Node版本当作Electron内置Node版本。

| 层次 | 决策 | 用途与取舍 |
|---|---|---|
| 桌面 | Electron＋React＋TypeScript | 托盘、窗口、通知、进程生命周期在同一应用管理；体积较大，但避免首版增加另一套语言和跨平台桥接 |
| 开发构建 | electron-vite，npm锁文件 | 构建main/preload/renderer及独立worker；开发时固定兼容版本 |
| 采集 | Playwright＋与其版本匹配的Chromium | 两平台分别使用专用持久配置；不接管日常Chrome默认配置 |
| 存储 | SQLite＋better-sqlite3 | 单机数据、同步状态、提醒计划和迁移；主进程单写入者，提前验证Electron原生模块ABI |
| 解析 | 规则提取＋PDF.js＋DOCX/XLSX文本适配＋Tesseract.js本地OCR | 先结构化和正文，再常见附件；OCR结果保留原证据，不当作保证正确的事实 |
| 测试 | Vitest＋Playwright页面/应用场景 | 规则、数据库、调度边界和脱敏页面回放；真实平台只读验证单列 |
| 打包 | electron-builder稳定版，Windows用户级安装包 | 提前验证资源路径、浏览器资源、数据库原生模块与通知注册，避免只在开发模式可用 |

截至查阅时electron-builder默认文档入口指向未发布next文档；实现时使用稳定版对应文档，不照抄next API。所有确切版本开工时依据官方包、兼容性和本机安装结果写入锁文件及进度，不在方案中编造版本组合。

替代方案：纯扩展体积较小但依赖日常浏览器生命周期；Tauri外壳较轻但引入Rust和采集进程打包成本；服务器超出本轮已选范围。当前固定Electron本机路线，只有可行性验证失败才重新评估。

## 3. 用户使用流程

首次启动：选择数据目录或使用应用用户数据目录 → 依次打开两平台专用登录窗口 → 用户完成登录 → 程序验证课程入口 → 自动首次同步 → 展示课程和采集覆盖 → 发送一条本机测试通知 → 保存通知设置。

日常：Windows登录后按应用开关自启 → 托盘常驻 → 自动同步与提醒。关闭主窗口默认隐藏到托盘；菜单“退出”才停止采集与提醒，退出前清楚说明。自启可随时关闭，不注册需要管理员权限的系统服务，不阻止正常休眠。

任务详情始终分成：老师要求日期、系统截止时间、提交/完成证据、来源、最后校验时间。只给日期不补造时刻；未采集、未发现、识别不确定是不同状态。

主导航控制在四项：
1. 任务：今天、未来7天、逾期、待确认；按课程/平台筛选。
2. 课程与采集：已选课程、各入口覆盖、同步结果、需要登录及失败原因。
3. 通知中心：提醒、稍后提醒、确认已读与失败提示。
4. 设置：同步间隔、提醒节奏、登录管理、自启、缓存、备份/恢复。

## 4. 进程与模块边界

```text
React本地界面
    ⇅ 受限preload IPC
Electron主进程
  ├─ SQLite单写入者／查询与迁移
  ├─ 持久调度器／提醒队列／桌面通知／托盘
  ├─ 采集utilityProcess ─ Playwright专用浏览器 ─ 两个平台
  └─ 附件解析worker ─ 文本提取／PDF渲染／本地OCR
```

不引入Web服务器、Redis、消息中间件、容器或微服务。主进程只做短数据库事务与调度；浏览器、下载和OCR不阻塞界面。数据库仅由主进程写入，worker提交经过类型校验的结果。

IPC仅提供如读取任务、启动登录、请求同步、稍后提醒、确认本地要求、修改设置等明确操作；校验参数、发送端和外部URL。renderer禁用Node集成、启用contextIsolation与sandbox；网页正文以转义文本/安全片段显示，不执行平台HTML脚本。

外部任务链接只接受已验证的HTTP(S)站点链接，跳回日常浏览器或专用浏览器。采集登录发生在专用Chromium，不加载到有本机权限的Electron页面。

## 5. 登录与浏览器生命周期

两个专用profile：icourse和xjtu。一次仅允许一个实例占用同一profile；登录和后台采集共享同一平台配置，通过互斥切换，不同时启动两份。

认证状态：`unknown → checking → ready / needs_login / challenge / network_error`。只有明确认证跳转或登录页证据才能判定过期；超时、证书、页面变更不能统一弹“重新登录”。

后台优先验证无头采集；若平台不兼容，在相同数据目录排他切换至专用有界面浏览器验证。不能靠禁用证书校验、验证码破解或绕过访问限制维持运行。对用户展示正常登录窗口后，停止自动操作认证控件。

保留正常会话跨应用重启复用，不在每轮清空profile、不主动登出。记录需人工重新登录次数和原因，观察登录复用效果；会话寿命是平台决定，不承诺特定天数。主界面关闭不关闭主进程，日常Chrome关闭不影响专用采集浏览器。

profile含认证秘密，仅放在用户应用数据目录、不进入源码、普通导出、Git、调试截图或全局记忆。不给“整个profile已经加密”的未经验证承诺；依靠专用目录与当前Windows用户权限隔离，具体保护效果需实测。

## 6. 平台适配契约

用三个显式适配器，避免提前开发通用插件框架：
- `xjtu-lms`：课程发现、首页待办对照、课程作业/测试/公告、详情与提交状态。
- `icourse-mooc`：普通MOOC新界面，课程ID＋tid，测验作业、考试与公告。
- `icourse-spoc`：SPOC旧界面，课程ID＋可观察期次，测验作业、旧/新版考试与公告。

统一方法语义（拟实现）：
`checkAuth()`、`discoverCourses()`、`scanCourse(course)`、`readTaskEvidence(task)`、`readAnnouncements(course)`。

每次扫描返回：记录、覆盖入口、是否读完分页/懒加载、明确空状态、错误及可重试性、开始/结束时间。结果不仅是任务数组；首页成功不能代表该平台全部成功。

读取顺序：
1. 校验登录与页面就绪信号。
2. 自动发现所有已选课程，分页/懒加载读完，保留活动学期和期次。
3. 遍历课程任务、考试、公告，展开只读详情以获得状态和证据。
4. 对新/变更正文及附件生成解析工作。
5. 对差异化个人或小组要求保留当前账号可见值及适用对象，不能用公共课程时间覆盖个人时间。

不进入答题会启动计时的页面，不点击开始考试、前往作答或提交操作。有效提交次数/记录可作为证据；分数锁定、未评分、零分不等于未交。互评作为独立阶段，不随作业提交一并完成。

先用已验证页面结构完成读取。开发时仅依据真实可观察的授权读取请求评估结构化接口；建立字段与页面对照后才替换。只因路径猜起来像API不足以使用；不得伪造接口清单。

## 7. 自动同步与数据合并

默认配置：每30分钟扫全部活动课程的任务/公告列表及其状态；新建或变更项读取详情。每24小时完整校验课程、任务详情和缺失项；没有可验证内容版本的页面不能只信旧指纹，必须周期重读。自动发现课程包含在周期内，不能只每天一次发现新课。

初次启动、网络恢复和唤醒时检查是否已错过计划：过期则补采，尚新鲜则不重复发起。主进程每分钟左右检查持久计划；不依赖一个持续存活的setTimeout作为真相。精确间隔是初始策略，按真实限流与资源占用调优。

同平台默认串行，两个平台可低并发；单平台只运行一轮，手动刷新与自动计划合并，避免叠加。页面超时和重试有上限；失败退避建议5/15/30分钟至上限，认证挑战暂停该平台并给一次有效提醒。连续失败不会无限开浏览器窗口。

数据库合并：按平台/本地账号/课程/期次/远端任务ID和阶段去重；一门课程的完整成功结果在事务中更新。局部成功只更新已确认记录，覆盖标记为partial。新状态、版本事件和需要重排的提醒在同一数据库事务提交。

缺失、空列表、未知状态规则：
- 加载中、登录页、报错页面或分页未完成不算合法空列表。
- 明确完成的扫描也不会立即删除历史任务；先标记本次未见，按完整复核与平台明确取消证据处理。
- 某字段未读到，不写null覆盖上次成功值，而是保留旧值并标记陈旧/未知。
- 已提交、退回、重交可以变化，只接受明确的新证据，不设计为永远单向完成。
- 同名跨平台课程只允许关联展示，不自动合并任务。

界面显示每个平台、课程、内容类别的最近成功时间和失败；可见任务数量与完整覆盖分别报告。数据超过建议2小时未成功校验即显示明显提示，但提醒仍可使用最后已知时间，并注明尚未重新核对。

## 8. 数据模型与日期语义

建议使用以下逻辑表；实现时允许在相同语义下简化，不引入ORM自动迁移黑箱：

| 表 | 关键内容 |
|---|---|
| platform_accounts | 本地账号标识、平台、认证状态、profile引用，不存密码 |
| courses | 平台/账号/课程ID/期次唯一键、学期、名称、活动状态 |
| tasks | 远端ID、类型/阶段、标题、平台提交状态及证据、来源链接、可见性 |
| requirements | task或公告关联；system/teacher来源类型；独立稳定标识；精度、时间、确认与完成状态、版本 |
| evidence | 原文摘录、来源链接、附件hash/页码/区域、发布时间、采集时间、解析器版本 |
| documents | 文件指纹、大小与类型、缓存引用、提取状态、失败/限制、关联来源 |
| sync_runs / sync_coverage | 各轮及各课程/入口结果、完整性、错误、最近成功时间 |
| change_events | 新增、日期/状态变化与用户确认历史，避免只有最终值 |
| reminders | requirement版本、触发策略、计划时间、投递/确认状态、重试和去重键 |
| settings / schema_migrations | 同步与提醒偏好、数据库版本 |

一项任务可以有多个老师要求，例如上课交纸质稿、网上提交、之后互评。公告暂不能明确关联某作业时，保留为课程级老师要求，不靠相似标题强行挂接。

每项日期包含：`source_kind`、`precision(date/datetime/range/unknown)`、原文、原始时区、提取方式、确认状态。明确日期时保存`YYYY-MM-DD`；明确时刻保存UTC时间戳并显示Asia/Shanghai；考试开放/截止区间不压缩为一个日期。

老师说明“10月27日交”可结合开课学期提出年份候选，标记年份推断；不声称原文明确年份。不明“周五”“第8周”需可靠公告发布时间、校历起点及上下文，否则待确认。公告发布时间、附件上传时间、习题编号不是截止时间。

人工纠正作为覆盖层留存，不改写证据。来源更新后提示人工覆盖可能陈旧，不自动抹掉。任务完成与是否逾期分开建模；平台完成、老师要求完成、互评完成彼此独立。

## 9. 正文、附件与图片解析

处理链：发现来源 → 有限下载 → 校验类型/大小 → 计算SHA-256 → 文本/图片解析 → 日期与动作词识别 → 保存原文证据 → 关联要求或标记待确认。

优先处理作业说明、公告、教学进度表和直接关联附件，不递归抓取所有课程教材。明确展示自动发现范围；长课件可能含要求但不在优先范围时显示尚未检查，可由用户触发扩展扫描。

首版支持目标：
- HTML/纯文本：正文、列表、表格及图像替代文字。
- PDF：先PDF.js读文本；需要时逐页渲染，交本地OCR；整页/局部覆盖状态分开记录。
- DOCX：纯文本及表格顺序提取，必要时提取嵌入图片；优先评估Mammoth，表格关系须另保留验证。
- XLSX：用ExcelJS读取单元格/日期和相邻表头，不执行宏或公式；无缓存结果的公式日期待确认。
- PNG/JPEG/WebP：规范化后以Tesseract.js中文/英文识别，保留图片与位置证据。

Tesseract.js不直接支持PDF，不能把PDF直接传入OCR并声称已覆盖。PDF渲染→OCR需要单独验证。嵌入图片、扫描页和表格识别错误都是实际失败路径。

暂不支持的老格式DOC/XLS、PPT/PPTX、压缩包、加密文件和模糊手写图，显示具体限制及原链接；保留适配入口。此为明确格式边界，不能把“AB”解释成任意格式都已支持。

初始可配置保护：单文件25MB、OCR单次最多30页、单并发、单文件解析有时限。超限项标记部分解析并显示未处理页数，可排队继续，不静默截断后报成功。相同hash不重复OCR；URL相同但内容hash变化则重新解析。

OCR置信度不等于时间语义可靠性。明确正文规则可直接建立teacher要求；模糊OCR、缺年、相对日期先建立候选及待核实提醒，不伪装为老师明确DDL。默认不调用外部模型，不上传课程正文、附件或登录状态。

## 10. 两类日期展示与提醒规则

```text
线性代数与解析几何I · 第三章作业
老师要求日期：10月27日交（未注明时刻）  [查看说明]
系统截止时间：10月30日 23:59           [打开平台]
日期不一致；老师要求完成状态与平台提交状态分别显示。
```

数据不设合并后的“真实截止时间”。用于列表排序时可取最近待处理提醒时刻，但排序值不显示为截止时间，也不能丢掉另一项。今天、未来7天、逾期按各requirement判断，卡片可归入多个视图，标签说明哪项到期。

默认建议：
- 有明确时刻：分别提前3天、1天、3小时；任务首次发现已在这些窗口内，合并为一条当前提醒而不补弹所有历史档位。
- 只有日期：前一天20:00与当天09:00，明确写“老师未注明具体时刻”；这些是提醒时间，不是截止时刻。当天稍后才发现则及时提示。
- 新任务/日期提前/日期冲突：单独变更提示，避免完全依赖固定提前量。
- 已经有效提交：仅取消平台已完成阶段的提醒；老师线下要求和互评不自动取消。
- 截止修改：取消被替代版本的未来提醒，新版本重新排程；取消或恢复要求须保留历史。
- 逾期、缺时刻、不确定日期分别表达；日期精度项在当天显示“今天要求完成，时刻未知”，次日才按日期级规则标记已过日期。

提醒去重键包含requirement稳定ID、版本、策略档位和渠道；两类日期即使相同也不误去重。可以同一桌面通知中汇总两项，但通知中心仍保留两条独立要求及状态。

数据库先记录投递任务，主进程调用系统通知并记录响应；通知请求与数据库无法构成跨系统原子事务，不承诺严格exactly-once。进程在投递前后崩溃时，结果未知的记录在通知中心可见，并以受限补发策略处理。只将明确点击/确认标为已读，不把API成功标为用户已看到。

建议勿扰23:00–08:00：通知中心立即记账；通常弹窗延至早上。明确截止即将在夜间过去的紧急任务按可配置紧急策略提示，首次设置展示这一行为。未确认提醒最多追加一次同日摘要，不无限弹窗；“稍后提醒”独立于“已完成”。

唤醒和启动后：先恢复持久计划、合并错过提醒；网络可用则刷新临近任务，在有界等待后按最后已知信息提醒，不因采集失败无限拖延。停止程序/关机/休眠期间不承诺送达。

## 11. 通知可达性与Windows打包

在开发早期验证Windows通知，打包后再验证一次。固定应用ID与开始菜单快捷方式/必要Toast注册，验证点击通知能回到对应任务；不能只验证开发窗口里的按钮变色。

应用内通知中心、托盘未读标记始终保留。若系统通知被关闭或勿扰拦截，显示测试结果与设置指引，不擅自更改系统安全/通知设置；没有事件不能声称看到了。需要额外渠道时再选择具体接收端，本轮不搭建邮箱或手机服务。

打包必须包含或首次按官方来源安装匹配的Chromium、OCR模型与worker资源，放到可写/可执行资源目录；不把浏览器或原生模块塞入无法执行的asar路径。安装包稳定版配置、native rebuild和模型资源均是早期冒烟点，不能临到交付才检查。

交付目标是Windows x64用户级安装包；不承诺免费获得代码签名信誉，不绕过系统安全警告。应用自启是可见设置，安装/开机自启效果属于最后本机验收，方案阶段不修改系统。

## 12. 数据目录、备份与恢复

运行数据使用Electron解析出的用户数据目录，不硬编码机器用户名，不放进源码目录：

```text
<app-user-data>/
  reminder.sqlite
  profiles/icourse/    profiles/xjtu/
  cache/documents/     models/ocr/
  logs/               backups/
```

SQLite用参数化SQL、外键、事务及有界写入；可使用WAL，但在线备份用SQLite备份能力，不直接复制一个可能有未合并WAL的数据库文件。每次迁移前生成一致性备份；备份恢复先在临时目录检查schema与内容，不覆盖运行中数据库。

用户手动完成、设置、老师日期校正均持久化；数据导出不含profile认证秘密。默认不上传遥测。日志记录平台、课程本地ID、耗时、错误码；剔除认证请求头、账号标识与含令牌的URL参数。原文证据在本地业务库与缓存中，不写全局记忆。

缓存可按设置清理，清理前引用检查，不清除用户校正和必要证据。运行日志轮转；项目长期记忆和关键决策不随运行日志过期。清理操作使用受限数据路径，不根据网页文件名拼接任意删除路径。

当前没有Git，不强制初始化。开工前可保存受影响现有文档快照；实现中用里程碑记录变更与恢复办法。回退应用版本如遇不兼容schema，保留新库并使用明确备份副本验证；恢复旧备份会缺少备份之后的改动，不能称无损一键恢复。

## 15. 验证与完成标准

每一类证据分开报告：单元/回放通过不等于真实平台通过；打包成功不等于用户收到通知。所有项目在实现前均NOT RUN。

### 必测场景

| 场景 | 预期 |
|---|---|
| 第三章作业两日期 | 老师10月27日、系统10月30日23:59独立存在、展示与提醒，无合并截止字段 |
| MOOC 23:30与只给日期 | 不改为23:59，不给日期项编造截止时刻 |
| 已交未评分/分数锁定/零分 | 按有效提交证据判定；缺证据则unknown |
| 互评/线下要求 | 平台提交后仍保留未完成的其他阶段 |
| 同名跨平台/跨期次 | 不错并；两轮采集不重复 |
| 新选课/新任务/提前或延后/打回 | 自动发现、保存变更、只重排相关要求 |
| 列表瞬态为空/分页半途失败/未知字段 | 保留历史，partial或错误可见，不清空 |
| 单平台登录过期或网络失败 | 只影响该平台；故障提醒去重；另一个平台继续 |
| 模糊OCR/大文件/不支持格式 | 待确认或部分覆盖，不当作无要求 |
| OCR文档中包含恶意链接或指令 | 不执行脚本、不扩展访问、不外发数据 |
| 主窗口关闭/重启/休眠/时钟变化 | 持久计划重算与补采，不依赖旧内存计时器 |
| 通知边界崩溃 | 可见的投递未知状态及受限补发，无无限刷屏 |
| 迁移失败/恢复 | 原数据与备份可用，临时副本恢复通过后才操作正式库 |
| 安装包 | 离开开发工具可启动，浏览器/模型路径正确，SQLite模块可加载，通知点击可用 |

### 真实平台验收

- 重新人工核对当时全部已选课程，历史12/3/5课程数与7待办只作初始参考，不能硬编码。
- 自动扫描所有可访问课程和计划内入口；无法读取的项列明原因，覆盖不是100%时不得宣称全量成功。
- 至少两次真实定时同步，中间没有逐门打开课程或点击同步；测试时可以缩短间隔，真实默认仍为30分钟。
- 应用重启、日常Chrome关闭与主窗口隐藏分别验证；用户退出则按设计停止。
- 最终在本机跨至少一个正常使用周期（建议24小时）观察自动采集与登录，记录睡眠/离线区间。自然平台变更若没有出现，标注未观察，不伪造事件；用隔离fixture测试提前/延后。
- 通知API响应、实际可见、点击跳转分别记证据；需要用户首次登录和确认可见是产品验收，不能由工具输出代替。
